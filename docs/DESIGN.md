# BitRunner 设计文档 v0.1

> 2D 像素 · 回合制 · 背包整理 + 搜打撤 · PC 单机 · 单人开发
> 单局目标时长：15 分钟

---

## 1. 一句话定位

**把装备和战利品塞进同一个格子背包，在变强与变富之间做选择，然后活着把它带出去。**

主题包装：玩家是一名"数据跑者"，潜入崩坏的数据节点，背包里装的是硬件模块（装备）与数据残片（战利品）。敌人同样是跑者——它们也背着自己的包，也在做同样的取舍。

---

## 2. 核心循环

### 2.1 一局：15 分钟

```
仓库配装 → 进入节点(搜) → 回合战斗(打) → 撤离/阵亡(撤) → 结算入库 → 基地
   ↑________________________________________________________________|
```

| 阶段 | 时长 | 内容 |
|---|---|---|
| 配装 | 1-2 min | 从仓库挑选装备与消耗品，摆进背包格子 |
| 潜入 | 2 min | 行动场景选择路线 |
| 战斗/搜刮 | 8-10 min | 3-5 场战斗 + 2-3 次战利品取舍 |
| 撤离 | 1 min | 读条 3 回合，最危险的时刻 |
| 结算 | 1 min | 战利品入库/出售，升级设施 |

**背包是同一个持久实体**：基地里配好的背包直接带进图，图里捡的东西当场塞进去，撤离后原样带回。不做"局内背包 + 局外仓库"两套格子。

### 2.2 一周：7 次探索 + 一次缴债

```
第1天探索 → 第2天探索 → ... → 第7天探索 → 缴债
                                              ↓
                                  成功：进入下一周
                                  失败：游戏结束
```

- 每次出征消耗 **1 天**，无论撤离还是阵亡
- 第 7 次探索结算后**自动扣款**
- bit 不足 → 游戏结束
- 债务清零 → 通关

### 2.3 为什么这个循环成立

- **债务是硬倒计时**：不能无限刷低级图，必须在有限天数里提高单次收益
- **商人是唯一变现口**：战利品越多 → 背包越满 → 战力越低 → 越难活着带回来
- **装备是投资**：花 bit 买装备 → 打更深 → 更高收益，但与缴债直接竞争
- **保险箱是保底现金流**：即使阵亡，也有一点进度

> 每一周的核心问题只有一个：**这一周要"稳"还是"赌"？**

## 3. 背包系统（核心）

### 3.1 基本规格

- 基准背包：**6 × 5 = 30 格**，每格 32×32 px
- 物品形状：1×1 ~ 3×3，允许旋转（部分物品不可旋转）
- 物品以左上角为锚点占位，不可重叠、不可越界

### 3.2 物品分类

| 类型 | 占格 | 战斗作用 | 说明 |
|---|---|---|---|
| 武器 | 1×2 ~ 2×3 | 主动输出，消耗 能量 | 有冷却 |
| 护甲/模块 | 2×2 ~ 3×3 | 被动护盾/属性 | 相邻协同 |
| 工具/饰品 | 1×1 ~ 2×1 | 被动效果 | 小格填充 |
| 消耗品 | 1×1 | 主动使用，一次性 | 可进保险箱 |
| 战利品 | 1×1 ~ 2×2 | **无** | 纯价值，占格即代价 |
| 材料 | 1×1 ~ 2×2 | 无 | 回基地制造 |
| 货币/弹药 | 1×1 | 无 | 可堆叠，bit 存在仓库中 |

> 关键：战利品没有战斗价值。捡它 = 用战力换钱。这是全部张力的来源。

### 3.2.1 堆叠

- `bit` 是仓库中的可堆叠物品，不再单独维护一个钱包变量；债务与商人直接扣除/加入仓库里的 bit 堆。
- 弹药也是堆叠物品；抛射武器从同一背包扣除对应弹药。
- 堆叠物品只占一格，右下角显示数量；掉落/购买时可合并到已有堆。

### 3.3 协同（Adjacency / Row / Column）

协同规则写在物品数据里，支持四方向相邻、同行、同列三类条件。当前基础规则：

- 刀刃相邻刀刃：+2 伤害
- 护盾相邻护甲：+3 护盾
- 芯片相邻武器：该武器 +1 冷却缩减
- 武器相邻抛射物：+1 伤害
- 武器与靶向芯片同行：武器 +1 伤害（靶向阵列）
- 回收物相邻战利品：每件 +1 护盾（赃物模块）
- 回收物相邻机械：+2 护盾
- 冷却物相邻能量物：+1 护盾

协同只看**最终布局**，不看摆放顺序。玩家在配装期和战斗中都在解这个空间谜题。战斗背包中激活协同的物品显示金色描边，tooltip 显示具体协同加成。

### 3.4 战斗中的整理

- 每回合**第一次**移动/旋转物品免费
- 之后每次移动/旋转消耗 **1 能量**
- 目的：既有战术空间（临场换位触发协同），又不至于无限试错拖慢节奏

### 3.5 保险箱（Tarkov 式）

- 独立 **2×2** 小格子，**死亡后内容保留**
- 只接受 1×1 物品，且不能是武器/护甲
- 可放：战利品、材料、消耗品
- **保险箱物品不进入战斗背包，因此战斗中无法使用**（只读展示）
- 基地可整理；战斗胜利后的搜刮阶段可直接把战利品拖进保险箱
- 设计张力：这 4 格是放"保底收益"，还是放"救命药"？
- 基地可升级扩容（+1 格/级，MVP 上限 2 级）

## 4. 战斗系统（对称）

### 4.1 第一原则：玩家与敌人共用一套规则

敌人不是"数值 + 意图表"，而是**另一个跑者**：

- 同样的 能量
- 同样的格子背包
- 同样的物品与冷却
- 同样的邻接协同

一次战斗 = 两个背包互相对撞。代码里只有一个 `CombatActor` 和一个 `CombatEngine`，玩家和敌人的区别只在控制器（玩家输入 / AI）。

### 4.1.1 能量、护盾与弹药

- **能量**取代行动点：每回合提供固定能量，武器/工具按能量消耗使用。
- **护盾**取代格挡：每 1 护盾直接吸收 1 点伤害，且发生在护甲减伤之前；护盾不再在回合开始时由被动物品免费提供，必须消耗能量主动使用护盾物品（或由技能/状态提供）。回合开始仍会清空普通护盾，缓存可保留。
- **耐久**：武器每次发动、护甲每次受到伤害各消耗 1 点耐久；耐久归零后物品损坏并从背包移除。耐久写在 `PlacedItem` 上，随玩家背包跨战斗保留，战斗开始不会重置。
  **`ItemDefinition.MaxDurability` 必须显式声明，没有隐藏默认值**：`-1` = 未声明（武器/护甲会被 `ItemCatalog` 直接拒绝，启动即报错）；`0` = 明确不会损坏（只有野兽的「兽牙」这类天然武器用）；大于 0 才是可消耗的耐久上限。生效值统一读 `DurabilityMax`，它不做任何兜底。
- **弹药**：部分抛射武器（如脉冲发射器）需要背包内对应弹药；使用时消耗，弹药不足无法使用。
- 伤害顺序：原始伤害 → 护盾逐点吸收 → 护甲百分比减伤 → 扣生命。

### 4.2 战斗单位

| 属性 | 玩家 | 普通敌人 | 精英 |
|---|---|---|---|
| HP | 40 | 20-35 | 45-60 |
| 基础 能量 | 3 | 3 | 4 |
| 背包 | 6×5 | 4×3 | 5×4 |
| 消耗品 | 携带 | 0-1 | 1 |
| 战斗中重排 | 首次免费，之后 1 能量 | 不重排 | 每回合 1 次 |

### 4.3 敌人背包完全可见

战斗中直接显示敌方背包内容，没有战争迷雾。玩家能读到：

- 武器伤害、能量 消耗、冷却
- 护甲护盾
- 激活中的协同关系
- 哪些格是纯战利品

**敌人的战力 = 战斗格占比；敌人的奖励 = 战利品格占比。** 两者此消彼长——敌人也在做和玩家一样的取舍。

这条规则让"打谁"变成真正的决策：一个背着金雕像的清道夫很好打但很肥；一个塞满武器、几乎没有战利品的执行者很硬但很穷。

战斗胜利后搜刮时，双击或 Shift+左键可把物品快速转移到背包（背包满时自动尝试保险箱）；“搜刮全部”按钮会按顺序收集所有可容纳的战利品。保险箱接受能放进 2×2 的非武器/护甲物品（原来限定只能 1×1，2×2 的箱子等于只有 4 个单据位，装不下任何稍大的战利品，已取消）。

**搜刮不再用全屏弹窗。** 探索里搜到物资时，容器面板固定在左侧留白（`ShellRegions.LootDock`，A 账本与 E 状态之间那块 176×146），F1 背包 / F3 保险箱原样露在外面，直接拖进去。原来那块 86% 黑的全屏遮罩有两个硬伤：一是把整屏压黑、二是物品提示挂在 `TooltipLayer` 而遮罩在 `OverlayLayer`——提示被压在遮罩底下，于是“在搜刮窗口里悬停什么都看不到”。

**战斗结束不弹结算窗。** 胜（搜刮完毕点「返回地点」）、负、撤离、敌人逃离都是判定完成就弹栈回到上一屏，结论写进播报行和 G 区日志（日志跨模式连续，回去还看得见）。少一次“点击继续”，也少一层遮罩挡路。

### 4.4 敌人类型 = 配装人格

| 类型 | 战斗格占比 | 战利品占比 | 特征 |
|---|---|---|---|
| 清道夫 | ~30% | ~70% | 弱、肥，适合滚雪球 |
| 执行者 | ~85% | ~15% | 硬、收益低，挡路 |
| 猎手（精英） | ~60% | ~40% | 会重排背包、会用消耗品 |

行动场景可以预览行动风险；情报台升级后显示更具体的敌情。

敌人装备按种子随机生成，但**必选槽位**保持角色特征：重装守卫始终有 1 件大装甲、1 件小装甲、1 件小武器和 1 个治疗；无人机始终有抛射武器、弹药和芯片；野犬/松鼠始终保留兽牙与战利品。必选槽位先放置，可选战利品/弹药/小工具在剩余空间和预算内随机。生成器只使用 4×3 敌人背包能容纳的布局，放不下时回退到该角色的基线配装。

### 4.5 回合流程

1. **玩家回合**：3 能量，使用装备 / 重排背包 / 结束回合
2. **敌人依次行动**：每个敌人 3 能量，使用自己的装备
3. 冷却与状态结算
4. 循环

玩家永远先手——这是解谜游戏，先手权是玩家的规划空间。

### 4.6 敌人 AI

确定性贪心，按优先级打分，不使用随机数：

1. 能斩杀 → 用最高伤害武器
2. HP < 35% 且有治疗消耗品 → 使用
3. 最高期望伤害的可用武器
4. 预计承伤高时 → 使用护甲/护盾
5. 无可用动作 → 结束回合

相同局面永远得到相同动作，方便测试与玩家预判。UI 显示**下一步意图**，并随玩家操作实时更新。战斗背包中当前不能使用或正在冷却的物品会覆盖灰色遮罩，资源、材料、战利品等被动物品也会灰显，方便快速判断可点击资源。

### 4.7 协同

双方共用同一套协同规则。默认不显示协同描边；悬停物品时，只高亮与它触发联动的其他物品（金色描边），tooltip 显示伤害/护盾/能量/冷却加成。玩家在战斗中重排可以即时改变协同——这就是 1 能量 的价值。

### 4.8 数值骨架

| 项 | 初始值 |
|---|---|
| 玩家 HP | 40（`GameSession.ExpeditionMaxHp`） |
| 基础 能量 | 3 |
| 武器伤害 | 3-8 |
| 护甲护盾 | 2-6 / 回合 |
| 敌人伤害 | 4-10 |
| 单场战斗回合数 | 3-6 |

### 4.9 状态效果（战斗 Buff）

状态由 `BuffLibrary` 统一定义，支持强度叠层、次数层、唯一状态、持续时间与上限：

| 状态 | 效果 | 上限 |
|---|---|---|
| 过载 | 下回合能量 -1，消耗后移除 | 5 |
| 短路 | 每层受到伤害 +2 | 5 |
| 缓存 | 回合开始保留护盾 | 1 |
| 超频 | 每层造成伤害 +1 | 5 |
| 冷却 | 每层获得护盾 +1 | 5 |
| 腐蚀 | 每层回合结束造成 1 点真实伤害，无视护盾 | 8 |
| 过热 | 每层回合开始造成 2 点可被护盾吸收的伤害 | 6 |
| 纳米修复 | 每层回合开始恢复 1 生命 | 5 |
| 闪避 | 每层抵挡一次伤害，触发后消耗 | 3 |

同类状态重复施加会刷新持续时间并叠加强度；除过载/缓存/闪避次数外，回合结束统一衰减。超频来自靶向阵列；冷却来自冷却回路；腐蚀来自腐蚀飞针；过热来自电击棍；纳米修复来自修复包；闪避来自偏导器；过载来自超频核心与信号干扰器。

## 5. 搜打撤

### 5.0 潜入地点

潜入不再是扫雷棋盘。每次进入地图会生成一个带有地点主题的**行动场景**：

| 密钥 | 主题 | 行动倾向 |
|---|---|---|
| 旷野密钥 | 野地边缘 | 追踪、采集、隐蔽；低威胁、低价值 |
| 基础潜网密钥 | 废弃设施 | 扫描、侧门、破门、翻找 |
| 军用潜网密钥 | 军用节点 | 防线扫描、爆破、压制；高威胁、高价值 |
| 信号潜网密钥 | 信号深井 | 解析、追踪回波、干扰中继 |

密钥尺寸仍代表携带成本；地点主题、敌人池和物资池决定行动结果。

### 5.1 行动场景

- 每次地图开始时提供 **4–5 个初始行动**：至少一个低风险、一个高风险、一个撤退。
- 行动是 **2×2 特殊物品**，直接使用背包物品系统（`BagInventory`/`BagView`/拖拽），有单字图标，不走独立的行动按钮。
- 行动是网格中的物件；把左侧行动拖到右侧“已选行动”格，点击确认才执行。
- 左侧有“行动 / 背包”两个页签：行动页只显示行动物品，背包页显示玩家背包，可把治疗等可用物品拖到右侧已选格。
- 右侧已选格只允许一个物品：合法行动物品、或生命未满时可用的治疗物品；多个物品、武器、材料等无效物品会禁用确认并显示原因。
- 普通背包物品被用于探索时会消耗并推进一个阶段，与行动物品共用同一套校验和确认流程。
- 操作：右键旋转物品朝向；左键双击或 Shift+左键快速移动（背包 ↔ 仓库，行动 ↔ 已选行动）。
- 每个行动拥有自己的结果表，可能导向：
  - 物资（进入格子容器）
  - 战斗（进入战斗场景，胜利后回到当前地点）
  - 受伤
  - 警戒上升
  - 线索
  - 无事发生
  - 撤离
- 一次探索最多 3 个行动阶段；每次结果后生成下一组行动，最后只剩撤离。
- 结果采用权重随机，并受当前生命、背包剩余空间和警戒值影响。界面只显示低/中/高风险和可能的结果类型，不显示精确概率。

### 5.2 警戒与代价

- 高风险行动会提高警戒；警戒越高，后续行动越容易触发战斗。
- 生命低于危险线时，受伤结果的权重提高。
- 背包越满，物资结果越难转化为实际收益；背包空间仍是硬约束。
- 任何阶段都可撤退；提前撤退会放弃尚未取得的物资。

### 5.3 撤离

- 初始行动中始终有“撤退”；确认后立即结束本次探索并结算。
- 战斗胜利后返回当前地点，不会回到旧地图。
- HP 归零：背包丢失，保险箱保留。
- 撤退成功：背包 + 保险箱全部入库。

### 5.4 击杀与战利品转移

- 击败全部敌人后，**敌方背包原样打开**
- **不做独立列表 UI**：直接拖动敌方背包格子里的物品，放进自己的背包
- 放置预览与普通整理完全一致（绿/红落位、右键旋转）
- 装不下的留在原地，离开即消失
- 敌人的武器/护甲可以直接使用（不做损坏系统）
- 敌人背包里的纯战利品不影响其战力，但会稀释它——这是敌人自己的取舍

由此形成局内的正反馈：**打赢肥羊 → 变强/变富 → 更敢深入**，但背包空间始终是硬约束。

### 5.5 目标选择

多敌人遭遇时，所有敌人背包同时可见（4×3 小格），玩家自行决定先打谁：

- 先杀高输出武器持有者
- 还是先杀带金雕像但很弱的清道夫
- 或者用 AOE/控制拖住硬的，先吃掉肥的

这是对称系统带来的核心战术层。

## 6. 死亡与风险（硬核）

| 情况 | 结果 |
|---|---|
| 主动撤离 | 背包 + 保险箱全部保留 |
| 阵亡 | **只丢失本次探索中新捡到的战利品**；出发时就在背包里的装备原样保留，但耐久不恢复 |
| 仓库 | 永远不受影响 |

装备也占背包格，所以阵亡的代价是「这一趟白跑 + 装备带伤」，而不是「整套 loadout 消失」。

### 防死锁：靠裁决规则本身，而不是救济机制

早期设计过三条救济（仓库保底白板、连续阵亡送应急配装、保险箱兜底）。**2026-10-24 改为一条更根本的规则**：

> 阵亡只丢「这一趟捡到的」，自带装备一定回来。

这条规则天然消灭了死亡螺旋——玩家永远保有至少一套能出门的装备，不需要任何补发逻辑，也不需要判断"是否连续阵亡"。代价是硬核感下降，但因为装备耐久不回满，长期压力仍在（一件 T4 装备用 28 次就报废，阵亡只是让它带伤回来）。

保险箱仍然保留独立价值：它是**唯一能在阵亡时保住新战利品**的通道，4 格的取舍因此变得有意义。

## 7. 基地与养成

### 7.1 设施（当前 8 个页签）

| 设施 | 作用 |
|---|---|
| 商人 | 收购/出售，每日刷新 6 件库存（基地常驻，开局可用） |
| 潜网舱 | 放置潜网密钥，选择副本后下潜；组合件可开启特殊副本 |
| 比特矿场 | 每日在空格生成 bit，点击收取 |
| 制作站 | 放入材料，按配方制作装备/密钥 |
| 芯片（中央处理器） | 插槽安装芯片，永久提升基础属性与特殊效果（C-6） |
| 保险 | 子空间保险网络中枢：扩容保险箱（C-9） |
| 仓储 | 仓储设备：扩容基地仓库行数（C-9） |
| 通讯 | 通讯中枢：解锁 NPC 链路与任务板（C-9） |

情报台、终端未单独实现；悬赏并入通讯中枢任务板。

### 7.2 养成原则：**横向为主，纵向移出背包**

> **2026-10-24 修订**：原表述是「横向优先、纵向数值严格封顶」，与新增的 T1–T5 物品 tier 冲突。
> 修订后的原则不改动「格子解谜不能被数值堆叠破坏」这个内核，但允许纵向成长存在——只要它**不占战斗背包格子**。
> 详见 `docs/ITEM_TIER_PLAN.md` §0 与 §3。

纵向数值会杀死格子解谜，指的是**玩家把背包格子全部塞成数值件**。所以纵向成长改用背包之外的载体：

- **永久轴**：中央处理器 + 芯片（不占战斗背包，死亡不掉）→ 基础生命、基础能量、护甲基底
- **装备轴**：武器/护甲/工具的 T1–T5 档位（占格子，死亡即失）→ 武器伤害、护甲值
- **Build 轴**：词条 / 协同 / 形状（占格子）→ 倍率与特殊效果

背包内的成长仍以横向为主：

- 新物品/新词条进入掉落池
- 新背包形状与容量
- 保险箱 / 仓库扩容
- 新的起始条件

**保留的硬约束**：初始能量最多 +1，且不可叠加（能量是全游戏最敏感的轴）。

### 7.3 已实现基地设备

| 设备 | L1 | L2 | L3 | 升级费用 |
|---|---|---|---|---|
| 潜网舱 | 1×2 | 2×2 | 3×3 | 200 / 450 bit + 材料 |
| 比特矿场 | 1×1 | 2×1 | 2×2 | 100 / 250 bit + 材料 |
| 制作站 | 2×2 | 3×2 | 3×3 | 150 / 350 bit + 材料 |

- 潜网舱：初始只有 1×2，初始带一把永久基础密钥；密钥不消耗，组合催化剂会消耗；组合配方按物品集合匹配，优先最具体配方。
- 密钥尺寸与难度正相关：旷野/基础 1×1，军用 2×1，信号 2×2；高级密钥需要升级舱位才能带催化剂。
- 比特矿场：每格每天 5 bit；进入基地时填充，收取后以 `bit` 物品堆进入仓库，仓库无空间时保留产出，次日再填。
- 制作站：材料按配方消耗，产物进仓库；仓库满则拒绝制作。
- 基地右侧使用 8 个页签：商人 / 潜网 / 矿场 / 制作 / 芯片 / 保险 / 仓储 / 通讯，设施网格与背包共用同一套形状格和拖拽。
- 设施升级同时消耗 bit 与仓库材料；材料不足时升级失败且不扣 bit。

## 8. 任务

通讯中枢任务板：通过通讯链路解锁 4 个 NPC（老陈 / K-7 / 白鸦 / SEED），共 10 个任务、4 条链；每个 NPC 同时只能挂 1 个任务。任务只作为目标引导，全部复用现有系统：

| 类型 | 示例 | 奖励 |
|---|---|---|
| 交付 | 收集 5 件废料 | bit / 物品 |
| 猎杀 | 击杀 10 个敌人 | bit |
| 探索 | 完成 2 次军用潜网 | bit / 装备 / 通讯链路 |
| 危机 | 进入危机模式并撤离（C-10） | bit / 通讯链路 |

- 交付物可同时从基地仓库与随身背包扣除；完成后任务进入冷却。
- 链路锁定期间，通讯页签禁止修改设施网格（核心层 `ItemModificationGuard` 拦截）。

## 9. 经济、债务与商人

### 9.1 货币：bit

- 唯一货币；以可堆叠的 `bit` 物品保存在仓库中，债务结算与商店直接扣/加这堆物品
- 战利品只值钱，不能在战斗中直接使用
- 装备、消耗品、设施升级全部消耗 bit
- 无耐久/维修系统

### 9.2 债务（战役计时器）

主角欠款 **2700 bit**，分 3 周还清：

| 周 | 到期还款 |
|---|---|
| 1 | 600 |
| 2 | 900 |
| 3 | 1200 |

- 1 周 = 7 次探索；每次出征消耗 1 天，撤离/阵亡都算
- 第 7 次探索结算后自动扣款
- bit 不足 → 游戏结束
- 债务清零 → 通关
- 阵亡不会减少债务，只会少一天的收入

设计意图：债务是"必须冒多大风险"的旋钮。稳扎稳打能活，但还清需要更深的探索。

### 9.3 商人

基地常驻，两个功能：

**收购**
- 任何战利品/装备按 `Value` **全额**收购
- 把物品拖进商人货架才成交；货架空格就是当天的出售上限
- 卖出的物品会留在货架上，可按原价 **购回**
- 价值即卖价，读数简单，不设讨价还价

**出售（有限库存）**
- 每日刷新 **6 件**商品，每件 **1 个**
- 只卖装备/工具/消耗品，不卖纯战利品
- 售价 = `Value × 3`
- 商品以 6×5 物品格货架展示，和背包同样按形状占格
- 仓库为 10×6 格，面板内显示 10×6 视口（扩容后滚动），右侧竖向滚动条支持滚轮和拖动
- 拖入仓库才成交；当天售罄不补货，次日补满
- 示例：Blade 40 → 120；Plate 50 → 150；Chip 70 → 210

设计意图：
- 商人是"用钱换战力"的唯一稳定渠道
- 每日 6 件、每件 1 个，逼迫取舍
- 买装备的钱 = 少还的债 = 更高风险，形成核心 meta 决策

### 9.4 收入基准

- 一次成功撤离：基础潜网 ~180 bit，军用 ~320，信号 ~600，深网 ~1200
- 一次阵亡：只保住保险箱里的东西，自带装备带伤回来
- 每周 7 次探索是硬上限
- 周债务 400 → 700 → 1000 → 1300 → 1600 → 2000（此后固定）：**W4 起单靠基础潜网已交不起，W6 起必须能进信号或深网**

> 详细推导见 `ITEM_TIER_PLAN.md` §5.2。债务曲线本身就是进度门禁——它把「升级潜网舱」从可选变强变成活下去的必要条件。

### 9.5 防死锁

- 阵亡只丢本次新捡的战利品，自带装备一定回来（已实现，见 §6）
- 保险箱是唯一能在阵亡时保住新战利品的通道
- 商人永远收购，哪怕只卖 10 bit
- 债务无限，因此**收入曲线必须随地点档位上升**，否则中期必破产（见 `ITEM_TIER_PLAN.md` §5.2）

## 10. 技术架构

```
Assets/_Project/
  Core/           纯 C#，asmdef 隔离，不引用 UnityEngine
    Grid/         形状、旋转、占位、邻接
    Inventory/    背包实体、增删移、空间查询
    Items/        ItemDefinition（纯数据）、物品库
    Combat/       CombatActor、CombatEngine、协同、状态、事件
    Brains/       EnemyBrain（确定性贪心 AI）
    Expedition/   行动场景、行动结果表、加权结果
    Loot/         掉落表、战利品转移、种子化 RNG
  Game/           MonoBehaviour：视图、动画、输入、UI
  Data/           ScriptableObject 定义
  Art/            像素资源
  Tests/          EditMode 单测
```

**关键：`CombatActor` 同时表示玩家和敌人**，只有 Brain 与输入源不同。
敌方背包复用 `BagView`（只读模式），战利品转移复用同一套拖拽逻辑。

原则：

- **Core 层可脱离 Unity 跑测试**（格子 bug 是这类游戏最大的时间黑洞）
- 战斗使用种子化确定性 RNG，可复现、可回放
- 存档 JSON + 版本迁移，存 `Application.persistentDataPath`
- UI 用 uGUI（成熟、可控、像素字体好处理）
- Unity 版本：待定（建议 Unity 6 LTS）

### 数据驱动

```
ItemDefinition      id, 名称, 形状, 分类, 价值, 词条, 协同, 冷却
BagDefinition       宽, 高, 允许形状
EnemyDefinition     HP, 意图序列, 掉落
NodeDefinition      类型, 权重, 内容池
LootTableDefinition 条目, 权重, 数量范围
UpgradeDefinition   设施, 等级, 花费, 效果
```

## 12. 待定项

- 行动场景的随机结果是否需要进一步做成可视化概率
- 是否需要保险（付费找回装备）作为中期解锁
- 是否加入多角色/多背包流派
- 敌人配装是纯手工模板还是"预算生成器"（建议 MVP 手工，之后做生成器）
- 多敌人遭遇上限（建议 MVP 最多 2 个，精英战 1 个）
- 是否允许玩家攻击/破坏敌人背包中的物品（暂不做）
- 债务是否允许提前还款 / 部分还款
- 商人是否允许付费刷新库存
- 战役长度是否固定 3 周，或做成无尽模式
- 存档云同步（暂不做）
