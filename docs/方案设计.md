# 探索盘重构方案：参考《末日拾荒者》的格子物件语言

## 1. 参考图拆解

参考图不是“地图 + 数字提示”的棋盘，而是一个由多个网格组成的叙事界面：

- 顶部：大块叙事文本，描述当前地点与事件，是界面的视觉主体。
- 左侧：细长的角色状态栏，用分段条显示生命、疲劳、负重等，而不是一排大数字 HUD。
- 中部：两个并置的方格区域。左侧是“可用项目/行动”的图标格，右侧是“已选择的项目”格；选择通过把图标放入格子完成。
- 右下：当前物品/行动的详情卡，包含轮廓图、名称、属性和数量。
- 左下：行动日志，使用暗色背景和单色小字。
- 右下/中下：明确的“确认”按钮，执行当前选择。
- 视觉：黑底、深灰面板、1px 硬边框、无圆角、低饱和色、图标和文字都像“物件”一样落在格子里；没有明亮的扫雷数字和色块棋盘。

## 2. 当前问题

- 7×7 的格子目前直接显示“数字/物/敌/陷/出口”，本质仍是扫雷棋盘，视觉和交互都像抽象谜题。
- 数字是主信息，压过了地点、物件和叙事，和背包整理/格子物件的设计语言冲突。
- 地图、背包、物资箱、商店各自使用不同的信息层级；探索界面没有《末日拾荒者》那种“叙事 + 物件 + 行动选择”的统一感。
- 左键直接触发、右键标记，缺少“选择目标 → 选择行动 → 确认”的回合感。

## 3. 目标与非目标

### 目标

- 让探索地图首先被读成“一个装着未知物件的格子盘”，而不是“一个等待点开的数字棋盘”。
- 用行动图标代替纯文字操作；行动本身也以格子物件的形式出现。
- 保留探索的核心风险与资源取舍，不推翻现有地图生成、敌人物资和战斗流程。
- 与现有背包、物资箱、商店的格子语言一致：暗色槽位、彩色物件、选中边框、详情卡。

### 非目标（本轮不做）

- 不改成实时移动或自由角色行走。
- 不重做 7 天债务、战斗、背包、商人经济。
- 不引入新的大系统（技能树、装备耐久、复杂光照）。
- 不在第一阶段删除扫雷式相邻威胁计算；先把它降级为“扫描读数”。

## 4. 新探索盘结构

### 4.1 屏幕分区（640×360 参考分辨率）

```text
┌──────────────── 顶部叙事 / 当前地点 ────────────────┐
│  “你蹲在断裂的服务器架后。前方有三个热源……”          │
├──────┬──────────────────┬───────────────────────────┤
│ 状态 │                  │  行动盘（3×2 物件槽）       │
│ 生命 │   探索盘 7×7      │  [扫描][搜索][交战]        │
│ 负重 │   物件格           │  [标记][撤离][使用]        │
│ 威胁 │                  ├───────────────────────────┤
│ 物资 │                  │  已选行动槽 + [确认]        │
│ 天数 │                  ├───────────────────────────┤
│      │                  │  物件/行动详情卡            │
├──────┴──────────────────┴───────────────────────────┤
│ 日志：> 扫描 C4：信号噪声很高……                      │
└─────────────────────────────────────────────────────┘
```

- 探索盘：7×7，每格约 28px，格间 2px；总宽约 210px。保留 7×7 以维持现有难度与测试。
- 行动盘：3 列 × 2 行，每个行动是一个 1×1 物件图标，带短标签；选中后放入“已选行动”槽。
- 详情卡：显示当前格子的物件轮廓、名称、类型、相邻威胁、可用行动；也用于显示行动说明。
- 状态栏：生命分段条、背包负重、剩余威胁、剩余物资、天数；不再使用顶部整条 HUD。
- 日志：保留 3–4 行历史，用 `>` 前缀和低饱和绿/青色；错误用暗红。

### 4.2 探索格显示规则

| 状态 | 显示 | 说明 |
|---|---|---|
| 未探查 | 深色封条格 + 小号“未”或斜向封条 | 不显示大问号，不显示数字；可被标记 |
| 已扫描安全 | 空槽 + 右下角 1–3 个红点 | 红点表示相邻威胁，不显示阿拉伯数字主标签 |
| 物资 | `箱` 形物件，暗黄 | 选中后可执行“搜索” |
| 敌人 | `敌` 形物件，暗红 | 选中后可执行“交战” |
| 陷阱 | `陷` 形物件，橙色 | 仍可在扫描时触发；后续可改为排险行动 |
| 出口 | `门` 形物件，青绿 | 选中后可执行“撤离” |
| 已清理 | 极暗空槽 | 不写“空”字，避免满屏文字 |
| 标记 | 右上角小旗/`标` 角标 | 右键可直接标记，也可用行动盘标记 |

关键：**数字不再是格子主视觉**，只作为边缘红点/详情卡读数。这样既保留扫雷信息，又不再像扫雷。

### 4.3 行动流程

1. 左键点击格子：选中，顶部叙事和右侧详情更新。
2. 行动盘根据目标启用行动：未知格 → 扫描/标记；物资 → 搜索/标记；敌人 → 交战；出口 → 撤离；背包物品 → 使用。
3. 点击行动图标：图标进入“已选行动”槽，确认按钮亮起。
4. 点击“确认”：执行行动，写入日志；清空行动槽，刷新地图和状态。
5. 右键保留快速标记；双击可执行当前默认行动（扫描/搜索/交战/撤离），作为熟练玩家的快捷方式。
6. 扫描只揭示物件，不自动打开物资箱/进入战斗；玩家再选择“搜索/交战/撤离”，让物件和行动形成两段式节奏。

### 4.4 叙事与日志

- 顶部叙事根据选中格生成 2–3 行文本，例如：
  - 未知：“信号被噪声覆盖。你只能看见一格未解析的轮廓。”
  - 安全：“一段空旷的通道。附近有 2 个威胁信号。”
  - 物资：“一个半埋的物资箱，锁扣还在。”
  - 敌人：“热源正在移动，对方也背着一个包。”
  - 出口：“出口就在前方。确认撤离会结束本次探索。”
- 日志记录动作结果，例如：
  - `> 扫描 C4：发现物资箱。`
  - `> 搜索 C4：取得 3 件物资，箱内还剩 1 件。`
  - `> 交战：热源 A 进入战斗。`
  - `> 撤离：本次探索结束。`
- 行动失败也写入日志，不只改一行底部提示。

# 推翻扫雷：行动场景方案 v2（替代上一节）

> 用户决定：不再保留扫雷、7×7 探索盘、红点威胁和扫描扩散。每个地图本身就是一组初始行动选项；每个选项都可能导向不同结果。上一节方案作废。

## 1. 参考图的真正模式

参考图不是地图界面，而是“遭遇/地点”界面：

- 顶部是地点与事件的叙事。
- 左侧状态条。
- 左侧格子列出**当前可采取的行动**，每个行动是一个物件图标。
- 右侧格子放**已选择的行动**，底部确认后才执行。
- 执行后，结果通过叙事、日志、战斗、物资箱或状态变化反馈。
- 右下详情卡说明当前行动/物件，左下日志保留历史。

因此探索不再是“点开格子找出口”，而是**在一个地点中连续做选择**。地图实例 = 当前地点的行动状态。

## 2. 新探索规则

### 2.1 单次探索的结构

- 进入地图时生成一个**行动场景**，包含地点标题、入场叙事和 4–6 个初始行动。
- 每个行动都是一个格子物件：图标 + 短名 + 风险描述。
- 选择一个行动后，行动进入右侧“已选行动”格，点击确认执行。
- 行动结果由权重表与当前状态共同决定，可能产生：
  - 物资：打开箱子/拾取格，进入现有物品界面。
  - 战斗：进入现有战斗场景，胜利后回到本场景。
  - 伤害/警戒：损失生命，或提高后续风险。
  - 线索：揭示新行动，或解锁撤离路线。
  - 阶段推进：进入下一组行动。
  - 撤离：结束探索并结算。
- 执行后生成下一组行动；一次探索由 3–4 次选择组成，直到撤离、死亡或战斗失败。
- 初始行动中始终保留一个**撤退/撤离**选项；提前离开会少拿物资，但不会强迫玩家继续赌。

### 2.2 行动示例

地点：废弃中继站

| 初始行动 | 风险 | 可能结果 |
|---|---|---|
| 静默扫描 | 低 | 获得线索；发现物资；触发警戒 |
| 撬开侧门 | 中 | 取得物资；遭遇敌人；触发陷阱 |
| 正面破门 | 高 | 高价值物资；必战；受伤 |
| 沿外墙绕行 | 中 | 找到新入口；无事发生；被伏击 |
| 撤退 | 安全 | 立即撤离，保留已拿到的物资 |

行动不是固定六种；每个地点根据主题生成自己的行动池。野外、设施、军方、信号站点使用不同的行动和结果表。

### 2.3 结果不是纯随机

- 每个结果有基础权重，并根据当前生命、背包空间、警戒值、已选行动进行调整。
- 界面只显示“低/中/高”风险与结果倾向，不显示精确概率。
- 同一个行动在不同状态下可能导向不同结果，例如低生命时“破门”更容易受伤，高警戒时“绕行”更容易被伏击。
- 随机种子固定，便于测试和复盘。

## 3. UI 结构

不再有地图格。界面只保留行动物品格与结果：

```text
┌──────────────── 地点标题 / 叙事结果 ────────────────┐
│  废弃中继站：侧门后传来电流声。                       │
├──────┬─────────────────────┬─────────────────────────┤
│ 状态 │  可选行动 2×3       │  已选行动格 + [确认]     │
│ 生命 │  [扫描] [侧门]      │  [侧门]                  │
│ 负重 │  [破门] [绕行]      ├─────────────────────────┤
│ 警戒 │  [搜索] [撤退]      │  行动详情 / 结果预览     │
├──────┴─────────────────────┴─────────────────────────┤
│ 日志：> 选择撬开侧门。                                │
└───────────────────────────────────────────────────────┘
```

- 行动物品：每个行动是一个 **2×2 特殊物品**，直接复用背包的 `BagInventory`、`BagView` 和 `BaseDragInteraction`；物品上显示单字图标。
- 已选行动：右侧独立格子，只放当前选择；确认后清空。
- 详情：显示行动名称、风险、可能结果类型、当前状态影响，不显示精确数值概率。
- 叙事：顶部 2–3 行，执行后更新为结果文本。
- 日志：保留 4 条，用 `>` 前缀；战斗、拾取、受伤、撤离都记录。
- 状态条：生命、背包剩余、警戒、探索阶段/天数。
- 物资结果使用现有 `BagView` + 拖拽 overlay，不再另做列表 UI。

## 2026-10-24 修复：设施升级看不到容器内的材料

**现象**：把废料/合金板/电路板收进零件盒后，潜网舱/矿场/制作站仍提示「材料不足」。

**根因**：`FacilityUpgrade` 统计材料走 `BagInventory.CountOf()`，而 `CountOf` 只遍历背包**顶层** `_items`，不进入 `PlacedItem.Container.Bag`。容器内容物对材料统计完全不可见。

**修复**：

- 新增 `Core/Inventory/ItemSearch.cs`：`CountOf`（穿透容器递归统计，最大 4 层）、`Has`、`TryConsume`（顶层优先、容器兜底）、`TryConsumeAll`（先整体校验再扣，任一不足则完全不扣）。
- `FacilityUpgrade` 的 `HasMaterials` / `RemoveMaterials` 改用 `ItemSearch`；材料需求聚合逻辑抽成 `Aggregate`。
- 取值范围按设计确认限定为**仓库 + 仓库内的容器**；保险箱与玩家背包不参与（保险箱是保底资产，不应被无声花掉）。
- 消耗顺序：先吃仓库顶层散放的材料，顶层不够才动容器；容器物品本身不消耗，只清空内容。
- UX：新增 `RequirementText(catalog, stash, bitCost, materials)` 重载，材料不足时输出「废料×2(有 1)」。该带数量文案**只放在底部消息栏**（升级失败时追加「需求：…」），不放进设施信息框——信息框只有 154×36、字号 8，多一行会压到「升级」按钮上。

**验证**：

- 新增 `ItemSearch` 测试 4 个（穿统计、顶层优先、不足时不扣、批量原子性）+ 设施测试 4 个（容器内材料可升级、顶层优先、失败不动 bit 与容器、需求文案含现有数量），EditMode **213/213 通过**。
