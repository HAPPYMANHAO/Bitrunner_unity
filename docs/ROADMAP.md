# BitRunner 开发路线图

原则：**每个阶段结束时游戏都能完整跑起来**，不做"半成品系统堆叠"。

内容审查与规划详见 `docs/CONTENT_DESIGN.md`（物品、敌人、协同、Buff、关卡、设施、标签化与物品等级）。

---

## Phase 0 — 工程基座（1-2 天）

- [ ] 创建 Unity 工程（版本待定，建议 Unity 6 LTS）
- [ ] 目录结构与 asmdef（Core 不引用 UnityEngine）
- [ ] 像素渲染设置：PPU 32、Pixel Perfect Camera、关闭抗锯齿
- [ ] 测试工程可运行（EditMode，NUnit）
- [ ] 基础 ScriptableObject 定义：Item / Bag / Enemy

**验收**：一个空场景 + 一个能跑通的 EditMode 测试。

---

## Phase 1 — 格子背包内核（核心，优先做对）

- [x] `ItemShape`：位图形状、旋转、归一化、包围盒
- [x] `BagGrid`：占位表、越界/重叠校验、放置/移除/移动/旋转
- [x] `Inventory`：多物品管理、邻接查询（四方向）
- [x] 自动放置（战利品快速收纳）
- [x] 单元测试：旋转、边界、重叠、邻接、移动后占位一致

**验收**：纯 C# 测试全绿；随机 1000 次操作后占位表与物品列表始终一致。

---

## Phase 2 — 背包 UI（可拖拽）

- [x] 6×5 背包网格渲染（32px 对齐）
- [x] 鼠标拖拽、预览占位、非法位置红色反馈
- [x] 旋转（右键，支持拖拽中与直接指向物品）
- [x] 快速移动（左键双击 / Shift+左键，背包↔仓库、行动↔已选行动）
- [x] 物品悬浮信息框
- [x] 调试用测试物品

**验收**：能用鼠标把 10 件不同形状物品随意摆放，无法重叠，视觉无半像素模糊。

---

## Phase 3 — 对称战斗（玩家与敌人共用引擎）

- [x] `ItemDefinition`（纯 C#）+ 初始物品池与 6 件联动物品（武器/护甲/工具/消耗品/战利品）
- [x] `CombatActor` / `CombatEngine`：HP、能量、护盾、冷却、状态、事件日志
- [x] 敌方背包渲染（复用 `BagView`）+ 意图预览
- [x] 点击使用装备；拖拽整理背包；目标选择
- [x] 邻接协同（双方同一套规则）
- [x] `EnemyBrain` 确定性贪心 AI + 下一步意图预览
- [x] 清道夫 / 执行者两套敌人模板
- [x] 战斗结束 → 直接从敌方背包格子拖拽战利品到自己的背包（统一 UI，无独立列表）
- [x] EditMode 测试全绿（AI 确定性、协同对称、伤害结算、冷却/状态；当前共 161 个）
- [ ] 精英模板（会重排背包、会用消耗品）
- [ ] 战斗动画与逐事件回放（当前敌人回合瞬时结算）

**验收**：能打一场 1v2；两个敌人的背包全程可见；击杀后可取走其装备与战利品；相同局面 AI 行为完全一致。
**状态**：已通过。实战模拟第 4 回合胜利，取走 8 件战利品、共 410 价值，剩余 3 格。

## Phase 4 — 搜打撤闭环

- [x] 行动场景生成（地点主题、4–5 个初始行动、3 阶段）
- [x] 行动结果表：物资 / 战斗 / 受伤 / 线索 / 警戒 / 撤退
- [x] 行动物品格、已选行动格、确认、详情、日志（2×2 特殊物品，复用背包系统）
- [x] 已选行动格可接收背包物品；行动/背包页签；单个合法物品校验，多个或无效物品阻止确认
- [x] 武器/护甲耐久：使用/受击各 -1，归零损坏移除；耐久随背包跨战斗保留
- [x] 战斗背包中不可用/冷却中的物品与资源/材料/战利品覆盖灰色遮罩
- [x] 搜刮支持双击/Shift+左键快速转移，以及“搜刮全部”按钮
- [x] 护盾改为消耗能量主动使用；移除每回合免费被动护盾
- [x] 敌人使用与玩家相同的能量/物品系统，从自身背包选择行动
- [x] 敌人装备按种子随机化，保留角色必选槽位；总尺寸不超过 4×3 背包
- [x] 新增同槽位装备变体（废铁甲/重型装甲/短刺/铁棍/钉枪/急救包/小饰物/数据核心）
- [x] 战斗胜利返回当前地点；物资进入格子容器
- [x] 行动权重受生命、背包空间、警戒影响
- [x] 撤退选项与撤离结算
- [ ] 阵亡结算（背包全失、保险箱保留）

**验收**：从进图到撤离/阵亡完整跑通，结算数据正确。

## Phase 5 — 基地、债务与商人

- [x] `CampaignState`：7 天/周、缴债、失败/通关（纯 C#，9 个测试）
- [x] `Merchant`：每日 6 件、每件 1 个、6×5 货架、拖拽出售/购回（纯 C#，13 个测试）
- [x] 基地场景 `BasePrototype`：仓库 + 背包 + 商人 + 债务 HUD
- [x] 仓库/背包双向拖拽（右键旋转），拖到商人货架出售
- [x] 商人 UI：6×5 物品格货架，拖入货架出售、拖入仓库购买、原价购回、次日补货
- [x] 债务 HUD：周/天、应缴、剩余债务、bit、距离缴款天数
- [x] 出征消耗天数，撤离/阵亡都算（回基地结算）
- [x] 第 7 天结算：扣款、进入下周、失败/通关
- [x] 战斗与基地共用同一个持久背包；阵亡清空背包
- [x] 潜网舱：1×2 → 2×2 → 3×3，永久密钥、组合副本、消耗催化剂
- [x] 旷野密钥：野地行动场景，野犬/松鼠，石头/树枝/垃圾
- [x] 比特矿场：1×1 → 2×1 → 2×2，每日每格 5 bit，点击收取
- [x] 制作站：2×2 → 3×2 → 3×3，材料配方制作，产物进仓库
- [x] 设施升级同时消耗 bit 与仓库材料
- [x] 堆叠：bit 作为仓库物品，弹药/货币可合并；护盾先于护甲吸收伤害
- [x] 仓库扩容为 6×10，5 行视口 + 竖向滚动条，支持滚轮/拖动滚动
- [x] 抛射武器消耗背包弹药（脉冲发射器）
- [ ] 情报台、终端
- [x] 保险箱：2×2、仅 1×1 非武器护甲、死亡保留、战斗中不可使用
- [x] 搜刮阶段可把战利品拖入保险箱
- [ ] 保险箱扩容
- [ ] JSON 存档 + 版本号 + 自动保存（出征前/回基地）

**验收**：连续 7 次出征后自动缴债；bit 不足进入失败；还清 2700 通关；商人每日刷新 6 件货架且可拖拽买卖；潜网舱组合副本可进入，矿场/制作站每日可用。
**状态**：基地 → 出征 → 战斗 → 战利品 → 回基地结算闭环已跑通（Day 1 → Day 2，背包持久）；设施页签、拖拽购买/出售/购回、组合副本、旷野低危层、矿场收取、制作、堆叠、护盾/弹药、行动/背包页签、跨战斗耐久、随机敌人配装与敌人物品化 AI 已验证。**161 个 EditMode 测试通过**。存档与保险箱扩容尚未实现。

## 风险清单

| 风险 | 应对 |
|---|---|
| 格子 bug 拖垮后期 | Phase 1 纯 C# + 测试，不碰 UI |
| 战斗节奏拖沓 | 敌人意图 + 单场 3-6 回合硬约束 |
| 硬核惩罚劝退 | 保底装备 + 应急配装 + 保险箱 |
| 美术量爆炸 | 先做 20 件物品的完整视觉，再批量 |
| 系统膨胀 | 每个新想法先问：是否复用现有系统 |
| 敌人配装内容量爆炸 | MVP 手工 3 套模板；之后做"预算生成器"，按战斗/战利品比例自动摆包 |
| 敌方背包信息过载 | 4×3 小格 + 悬停详情；最多 2 个敌人同屏 |
| 对称系统导致 AI 太强/太蠢 | 确定性贪心 + 固定优先级；先做可读性，再谈聪明 |
| 击杀后战力滚雪球 | 背包空间是天然上限；敌人装备不超模，收益与风险同源 |
