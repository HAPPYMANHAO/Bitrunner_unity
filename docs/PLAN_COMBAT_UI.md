# 战斗 UI 重做（Plan v3）

> 前情：`PLAN_UI_SHELL.md` 把三种模式收进一个外壳，Step 3 把战斗压栈。本文件只处理战斗界面本身——
> 上一版把敌人拆成"C 焦点 / F2 背包 / D 三行"，判断错了，这里重做。

## 0. 一句话

**战斗回到"敌人卡并排"的老结构**，但卡片搬进外壳的顶部带：A 账本在战斗中隐藏，让出左上角。
C 舞台、D 侧栏、F2 目标背包这三处"敌人信息的碎片"合并成一张自洽的卡。

> 尺寸前提：`CreateEnemies()` 现在最多同屏 **2 个**敌人（主敌 + 1 个随从）。
> 所以主版式是**两张 300 宽的卡并排**；第 3 个敌人的后备版式（206 宽、单列）写在 §2.3 末尾，现在不实现。

---

## 1. 现状为什么不好（诊断）

当前战斗（`final_combat.png`）把一个敌人的信息切成了三块：

| 信息 | 现在在哪 | 问题 |
|---|---|---|
| 名字 / 生命数字 | D 侧栏 42px 行 + C 舞台（重复两遍） | 同一个数字出现两次，密度两套 |
| 血条 | D 行 5px + C 舞台 8px（重复） | 视觉上"两条血" |
| 4×3 背包 | F2（只有一个） | **看不到另一个敌人背什么** |
| 护甲 / 减伤 / 意图 | 只在 C 舞台 | 不点选就不知道 |

三条硬伤：

1. **违反 `DESIGN.md` §4.3「敌人背包完全可见，没有战争迷雾」。**
   那条设计的目的是让"打谁"变成决策：背着金雕像的清道夫好打但肥，塞满武器的执行者硬但穷。
   现在必须先把每个敌人在 D 里点一遍、再去 F2 一个个看，才能比较——决策退化成操作。
2. **D 行只有 42px，装不下 4×3 背包（64×48）。** 所以背包被迫外置到 F2，
   而 F2 只能显示一个，于是又用 `SetActive` 把两个背包叠在同一位置"假装只有一个"——这是补丁，不是布局。
3. **顶部被切碎**：C 是 270×170 的大窗，D 是三条 42px 的横条，两个密度并存；
   战斗中最该被并排比较的东西，反而被拆到了屏幕两端。

> 结论：不是配色或间距问题，是"把敌人当成一个对象还是三份数据"的问题。
> 一张卡 = 一个对象，全部信息在里面；卡并排 = 直接比较。

### 2.2 为什么必须占满整条（A + C + D）

- 卡要并排比较，就必须共享同一条带。
- 只给 C+D（185..635，450px）：两张卡各 221px，4×3 背包（64）占掉三成，右侧只剩 150px 还得塞六行数字。

- 代价：战斗是唯一一个"跨洞"的模式。E/F1/F2/F3/G 五个外壳件仍然一动不动，所以整体还是同一个骨架。

## 3. 动画核查结果（本机实测，非推测）

代码在 Step 3 里并没有被删：`_animSteps / _fxPulse / _fxSpark / AnimPulseSeconds / FlashColor` 全在，
`Update()` 里 `_animating` 分支也在跑。实测（进入战斗后对 blade#2 调用 `OnPlayerItemClicked`）：

| 检查项 | 实测值 | 结论 |
|---|---|---|
| `_animating` | True | 动画启动 |
| `_animSteps.Count` | 1 | 事件被正确收成一步 |
| `_animItemRect` | `Item_2` | 找得到出发格子 |
| `_animTargetRect` | `EnemyRow_scavenger` | **落点是 D 的 42px 血条行** |
| t=0.05 脉冲 | active，尺寸 35×19，alpha 0.43 | 正常 |
| t=0.20 卡片底色 | (0.696,0.662,0.550) | 闪光插值正常 |

**所以动画没丢，是"落点错了 + 有一类不触发"：**

1. **落点是 42px 的血条行**，火花飞过去只让一条横线闪一下，几乎看不见。
   → 改为落在卡片整块（卡底色闪），一眼就知道"这只被打了"。
2. **消耗品用掉后从背包消失**，`BeginAnimationStep` 里 `TryGetItemView` 失败 → `_animItemRect = null`
   → 脉冲和火花都不出现，只剩目标闪光。
   → 改为**点击瞬间快照**格子矩形（`StartAnimations` 里一次解析，之后不再查背包），用掉了也照样从原格子飞出。
3. 其余保持：脉冲 = 物品图标 +3px、0.18s 缩小淡出；火花 9×9，0.06→0.19 从格子飞到落点；闪光 0.16→0.32 正弦插值。
4. 速度按钮留在 `SecondaryAction2`，动画期间可点（现有行为，不改）。

**可选加强（P2，不影响本次验收）**：`CombatEvent` 自带 `Amount` / `Shielded`，
可以在落点上浮一个 `-9`（伤害，`DangerColor`）/ `盾 -3`（`MutedColor`）/ `+6`（治疗，`HpColor`）的浮动数字，
0.5s 上移淡出。这是新卡布局下最值的一处反馈，但属于新增，先列出等确认。

## 7. 风险与取舍

1. **D 区在战斗中不存在。** 若以后要加"战斗技能列表 / 状态图标栏"，D 会重新需要。
   预留：卡片高 168 可以让出底部 20px 给一条 D 页签行，不动宽度。
2. **1 敌时单卡居中**（x = 170，宽度仍 300），与 2 敌（x = 16 / 324）位置不同。
   同一场战斗数量不变所以不会跳；但像素验收要按敌人数量分组比对。
3. **A 隐藏会掉"债务/bit"上下文。** 战斗中不会结算债务、也不会改 bit，出战斗即恢复，无信息损失。
4. **卡片 300×168 的右半列是"够用"不是"宽裕"**：`护甲 背 6 · 室 12` 这类行必须 9 号字，
   超过 200px 会截断——写死字符上限，不做自动换行。

## 9. 实施记录（已落地）

### 与规划的偏差

| 项 | 规划 | 实际 | 原因 |
|---|---|---|---|
| 卡内数字列 | 两列（左 能量/护盾，右 护甲/减伤） | **一列四行**（能量/护盾/护甲/减伤，x=88 宽 200） | 护甲/减伤要写满五种伤害类型（`护甲 烧2 毒12 室8`），98px 宽会换行撞进下一行。一列 + `HorizontalWrapMode.Overflow` 才稳 |
| 命中闪光 | 沿用 0.9 | **0.4**（`AnimFlashStrength`） | 0.9 是给旧 170×130 面板调的；300×168 的卡会被冲成米色、字全看不清 |
| 敌人卡宽度 | 300（两张） | 300（两张）+ `min(300, 均分)` 兜底 | 引擎现在最多 2 敌，但宽度算出来是通用的，3 敌自动收窄 |
| 搜刮全部 | F2 按钮 | 同左，文案带数量「搜刮全部（3）」 | 数量就是"还剩几件"，比单写"全部"有用 |

### 三处必须记住的坑

1. **战场带直接挂 `ScreenLayer`，`PopScreen` 不会替你销毁。**
   它跨 A/C/D 三个区，不属于任何一个洞，所以不在 `ShellScreen` 的四个容器里。
   第一次实测弹栈回探索时，两张敌人卡原样留在屏幕上——现在 `TearDown` 里显式 `Destroy(_band)`，
   播报行同理。
2. **`UiFactory.CreateText` 的 position 是"相对父物体左上角、y 向下为正"**，也就是要传 `-y`。
   播报行一开始写成 `(MessageLine.x, MessageLine.y)`，结果半截字被顶到画布外面。
3. **消耗品必须在用掉之前快照格子。** `OnPlayerItemClicked` 里 `SnapshotUsedItem(instanceId)`
   必须写在 `TryUseItem` 之前：修复包一用就从背包移除，动画开始时 `TryGetItemView` 必然失败，
   脉冲和火花都不出来。实测：用掉之后 `bagCount 7→6`、`_animItemRect = Item_5`（来自快照），
   脉冲坐标 `(-148,-90)` 与快照格子完全一致。
